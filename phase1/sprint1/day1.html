1. URL構造を分解する

https://example.com:443/products?id=10#detail

項目 値 説明 通信先決定に使われるか
scheme https 通信のプロトコルを規定。httpsかhttpが基本。 使われる
domain example.com DNSにてIPアドレスに変換される前のアドレス 使われる
port 443 サーバーのポートの指定 使われる
path /products サーバー内での資材や実行する処理の場所 使われない
query id=10 処理などに渡す引数 使われない
fragment detail 主にトップレベル遷移時に特定の場所項目を指すようにできる 使われない

DNSやSSLが出なかった理由

今回の観測では、DNS LookupやSSLが表示されないことがあった。

1. DNS Cache

最有力の理由。ブラウザまたはOSのDNSキャッシュが使われた場合、 DNS問い合わせ自体が発生しないため、DNS Lookupの時間が表示されない。

2. Connection Reuse

Chromeはkeep-aliveにより、既存のTCP接続やTLS接続を再利用する。 そのため、リクエストごとにDNS LookupやSSLが発生するとは限らない。

3. HTTP/2 multiplexing

HTTP/2では、1つのコネクション上で複数のRequestを扱える。 つまり、現代のWebでは「RequestごとにTCP接続する」とは限らない。
